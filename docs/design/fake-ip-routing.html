配置规则 = 顺序执行的代码，没有隐藏的智能仲裁

rules 数组本质是一串 if / else if，写规则的顺序就是执行顺序。 整张图里所有「为什么这条流量会/不会竞速、会/不会被拒」的答案，最终都能归结到同一个变量在某个时间点的状态： Destination 是域名还是 IP。

这也是我们在这次梳理里定位到的那个不对称之处——留一条实操准则：

任何在 profile.json 里配置「绕过 fake-ip」的域名，必须在 ip_version:6 reject（route.go:198）之前， 有一条明确的直连域名规则能兜住它——否则一旦它只解析出 AAAA 记录，会在 macOS 上被直接拒绝，即使 route 引擎其实知道它的域名。
